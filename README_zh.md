# spm-resolve

[English](README.md)

解析一个 Swift 包的依赖闭包，打印 pin，或打印可粘贴进 [depctl](https://github.com/0x1306a94/depctl) DEPS 的仓库条目。

解析写在 `~/Library/Caches/org.spm.resolve/<包目录名>`，不修改目标包。为什么不用 SwiftPM 自带的 `mirrors.json`，见 [docs/why_zh.md](docs/why_zh.md)。

## 环境

- macOS 15
- Swift 6.4

## 构建

```sh
swift build --product spm-resolve
```

## 用法

`spm-resolve --version` 打印工具自身的版本。包 URL 后面的 `--version <version>` 仍是该远程包的精确版本。

集成一个远程包时，先解析出依赖链，交给 depctl 拉取，再把清单改成本地路径。

```sh
spm-resolve https://github.com/hackiftekhar/IQKeyboardManager.git --version 8.0.3 --depctl
```

commit 用 `--revision` 代替 `--version`。`--depctl` 打印可粘贴进 DEPS 的仓库条目，里面包含 IQKeyboardManager 自己和它的依赖。把这段合并进 DEPS 后执行 depctl 同步，包会落在 `third_party/Packages/<仓库名>`。

同步完成后改写已拉下来的包：

```sh
spm-resolve rewrite third_party/Packages/IQKeyboardManager --dir-prefix ..
```

`--dir-prefix` 相对被改写的包目录。同级依赖会写成 `../IQKeyboardNotification` 这样的 path。`--dir-prefix` 下没有的 URL 保持不动。

`--depctl` 打出的是 `repos.common` 里的对象。合并进 DEPS，并在 `actions` 里于同步之后执行改写：

```json
{
  "version": "1.4.5",
  "vars": {
    "GITHUB": "https://github.com"
  },
  "repos": {
    "common": [
      {
        "url": "${GITHUB}/hackiftekhar/IQKeyboardManager.git",
        "commit": "0972dd6eded87c930fb6ad36b3c5ecd620f06894",
        "dir": "third_party/Packages/IQKeyboardManager",
        "comment": "8.0.3 version Generated by spm-resolve"
      },
      {
        "url": "${GITHUB}/hackiftekhar/IQKeyboardNotification.git",
        "commit": "efa705d7200edd95b6e31e65e25171f7e897f995",
        "dir": "third_party/Packages/IQKeyboardNotification",
        "comment": "1.0.7 version Generated by spm-resolve"
      }
    ]
  },
  "actions": {
    "common": [
      {
        "command": "spm-resolve rewrite third_party/Packages/IQKeyboardManager --dir-prefix ..",
        "dir": "."
      }
    ]
  }
}
```

depctl 读取 `url`、`commit`、`dir`。`comment` 只是备注。`actions` 在仓库同步完成之后执行。

```text
spm-resolve <package> [--depctl] [--dir-prefix <path>]
spm-resolve <url> --version <version> [--depctl] [--dir-prefix <path>]
spm-resolve <url> --revision <commit> [--depctl] [--dir-prefix <path>]
```

`<package>` 可以是包目录，也可以是 `Package.swift`。带 `://` 或 `git@` 的参数是远程仓库，必须带 `--version` 或 `--revision` 其中一个。`--version` 按精确版本解析。远程解析会在 `~/Library/Caches/org.spm.resolve/<仓库名>/<version 或 revision>` 写一个临时包，结果包含该仓库自己和它的依赖链，临时包不出现。

结果前固定打印一行 `--- spm-resolve ---`，用来和解析日志分开。默认打印全部 pin，列为 `kind`、`location`、`revision`、`label`，以制表符分隔：

```text
--- spm-resolve ---
git	https://github.com/example/Example.git	0123abcd	1.0.9
```

`--depctl` 只打印远程 Git 依赖，字段顺序固定为 `url`、`commit`、`dir`、`comment`。`dir` 默认是 `third_party/Packages/<仓库名>`，`--dir-prefix` 可改前缀。`comment` 末尾带 `Generated by spm-resolve`。条目按 URL 排序。

```text
spm-resolve Packages/xxx --depctl
```

```text
--- spm-resolve ---
[
  {
    "url": "https://github.com/hackiftekhar/IQKeyboardCore.git",
    "commit": "0123abcd",
    "dir": "third_party/Packages/IQKeyboardCore",
    "comment": "1.0.9 version Generated by spm-resolve"
  }
]
```

path、registry、本地 Git 依赖会跳过，并在标准错误输出一行 `skip`。空的 Git 列表打印 `[]`。

## 改写

depctl 同步完成后执行：

```text
spm-resolve rewrite <package> [--dir-prefix <path>]
```

`--dir-prefix` 默认 `third_party/Packages`，相对被改写的包目录。绝对路径和 `~` 按原样使用。命令从根清单顺着依赖声明往下走，不重新解析，也不访问 GitHub。同一个包根目录下的 `Package.swift` 和 `Package@swift-*.swift` 都会改。`.package(url:)` 改成相对当前清单目录的 `.package(path:)`。已有的 path 依赖保持原样，并继续往下走。registry 依赖打印 `skip registry`，不改。`--dir-prefix` 下没有对应包的 URL 保持原样，并打印 `skip`。

改写前把 `Package.swift` 复制为同目录的 `Package.swift.back`。备份已存在则保留。成功时打印改过的清单路径。

```swift
// Packages/xx/Package.swift
.package(path: "../../third_party/Packages/IQKeyboardManager")

// third_party/Packages/IQKeyboardManager/Package.swift
.package(path: "../IQKeyboardNotification")
```

## 依赖

`swift-package-manager` 来自 `https://github.com/swiftlang/swift-package-manager.git`，钉在 `88d5888f7f74b979f36aac41b4972aed58936fa2`。工具直接调用 `Workspace.resolve`，这个接口跟着 SwiftPM 主干走，不跟稳定发行版。改写使用 `swift-syntax` 604.0.0，对应 Swift 6.4。
